# Camora rule schema

All write operations require the latest integer `revision`. IDs are generated by Camora.

## Redirect

```json
{
  "type": "redirect",
  "source": "https://example.com/app.js",
  "sourceType": "urlFilter",
  "target": "http://localhost:3000/app.js",
  "targetType": "url",
  "enabled": true
}
```

Use `sourceType: "regexFilter"` for regular expressions. Use `targetType: "regexSubstitution"` when the target contains captured substitutions such as `\\1`.

## SourceMap

```json
{
  "type": "sourceMap",
  "source": "https://example.com/app.js",
  "sourceMapUrl": "http://localhost:3000/app.js.map",
  "enabled": true
}
```

## CORS

```json
{
  "type": "cors",
  "source": "https://api.example.com/",
  "allowOrigin": "*",
  "allowCredentials": false,
  "allowMethods": "GET, POST, OPTIONS",
  "allowHeaders": "*",
  "maxAge": 86400,
  "enabled": true
}
```

## Common errors

- `HOST_UNAVAILABLE`: Native host is not installed, Camora is not loaded, or the socket path differs.
- `REVISION_REQUIRED`: Read current state and supply its revision.
- `REVISION_CONFLICT`: State changed after the read; query again before deciding.
- `CONFIRMATION_REQUIRED`: Repeat only after explicit user confirmation and include `--confirm`.
- `RULE_NOT_FOUND` / `GROUP_NOT_FOUND`: Re-query instead of guessing an ID.
